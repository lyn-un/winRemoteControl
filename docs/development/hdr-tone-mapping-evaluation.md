# HDR→SDR 色调映射离屏评估

## 当前结论

2026-10-31 后续实现：当前 GPU 默认路径已改为桌面肩部映射，不再将 Direct2D 候选
失败作为整个任务的终点。以下 Direct2D 表格保留为候选历史记录，不代表当前生产算法。
新策略详见下节；完整本机回归和双机基本验证已完成，性能矩阵结果另行追加。

## 已选择的桌面 GPU 策略

输入仍为线性 scRGB，先以实际 SDR 白电平归一化。NaN 以位模式识别后归零，
无穷截到有符号 FP16 有限边界；避免依赖浮点 NaN 比较在不同 shader 优化下的行为。
负 RGB 分量通过向相同亮度的灰轴收缩处理，亮度使用线性 sRGB/Rec.709 系数
0.2126/0.7152/0.0722。然后以最大 RGB 分量控制统一压缩比例，避免分别裁剪三个通道。

固定 knee k=0.75：峰值 p<=k 不变；p>k 时，q=k+(1-k)(p-k)/(p-k+1-k)，RGB 乘 q/p。
这是对 Reinhard 的 x/(1+x) 压缩做平移和缩放的项目桌面适配，knee 处函数及一阶导数连续。
不是原论文完整摄影算子、不是 BT.2390/ACES，也不宣称感知色相或广色域完全无损。
无需输入 MaxCLL、不根据帧内容调曝光，无额外纹理和 GPU→CPU 读回。
映射后的线性值仍经原 sRGB RTV 编码一次；NV12 矩阵及协议保持不变。

同一归一化灰阶在80/160/200/320nit下均输出：
0,10,36,118,188,225,240,245,248,250,252,253。
中灰保持118；普通白变为240而非255，这是为超白高光留空间的明确取舍。
双机观察中用户确认“画面似乎正常”，但这不是物理亮度或色度测量。
当前硬件全 FP16 位模式、混合RGB和奇数尺寸对双精度 CPU 参考最大误差为1。

CPU 强制诊断和 GPU 不可用时保留旧裁剪兼容路径，颜色可能与新 GPU 路径不同；
日志区分 `desktop_reinhard_shoulder` 与 `legacy_or_sdr`，不把兼容回退描述为相同算法。
新 shader 与旧裁剪共用资源和编译产物，没有额外 D2D 专属资源失败分支；整体 GPU
初始化失败仍沿用已有 CPU 回退，设备丢失沿用采集错误处理。

参考：[Reinhard 等人的原论文](https://www.cs.utah.edu/docs/techreports/2002/pdf/UUCS-02-001.pdf)。
灰轴收缩与固定 knee 是本项目明示的工程策略，不是论文原文的参数或色域认证。

## Direct2D 候选历史结论

真实 SDR 白电平查询已接入采集。Direct2D HDR Tone Map 候选已实现，但未通过桌面亮度门槛，
因此该候选没有接入产品默认路径，也没有新增产品命令行开关。最初阶段曾保留旧裁剪，
后续已改用本页上方描述的桌面肩部策略。本节仅保留当时的候选评估记录。

## 候选处理链

`KHdrToneMapper` 使用采集对应的 D3D11 设备建立 D2D context，复用 FP16 输入/输出纹理、
bitmap 和 effect：scRGB FP16 → HDR Tone Map（SDR mode）→ White Level Adjustment →
线性 FP16。后续原有 BGRA 转换器按 SDR 白电平归一化，再通过 sRGB RTV 编码一次。
FP16 阶段 White Level Adjustment 的 input/output white 均为 80 nit，保持 scene-referred
单位，不重复归一化。输出使用 alpha ignore，最终 BGRA alpha 固定为 255。

不依赖第二张显卡或跨卡共享；输入纹理若无 D2D 所需绑定，复制到同设备复用纹理。
调用线程必须串行持有原有采集上下文锁。候选不采集桌面、不更改显示设置。

输入内容峰值不能从显示器峰值推定：评估固定扫描 1000/2000/4000 nit 三种策略参数，
不是实测 MaxCLL。输出峰值取参考 SDR 白电平（80/160/200/320 nit）。
该组合未被选定为生产策略；没有引入动态曝光、CPU 整帧峰值扫描或 GPU 归约。

## 颜色门槛与结果

运行前固定门槛：18% 线性灰输出与参考 sRGB 约 118 的差值不超过 12；SDR 白输出至少 230；
1.25/1.5/2/3/4 倍白的高光阶梯至少出现 4 次可区分变化；灰轴中性、单调，alpha=255。
这些门槛不能在失败后放宽来启用候选。它们是桌面适用性工程筛选，不是色度学认证。

硬件与 WARP 的灰阶编码结果一致。各组的三种输入峰值参数得到相同灰阶结果：

| SDR 白电平 | 18% 灰 | SDR 白 | 桌面门槛 |
| --- | ---: | ---: | --- |
| 80 nit | 88 | 194 | 不通过，明显压暗 |
| 160 nit | 122 | 230 | 通过这组灰阶筛选 |
| 200 nit | 135 | 236 | 不通过，中灰偏高 |
| 320 nit | 135 | 235 | 不通过，中灰偏高 |

所有组灰轴中性且单调，但不能因此认为候选适合桌面，也不能由灰阶结果证明饱和色/色域处理正确。
这是当前 effect 链及参数策略的失败，不是证明所有 Direct2D 调用方式或其他 tone map 算法都不可用。
必须先重新确定桌面映射策略与白附近取舍，再评估生产接入；不直接替换成未经论证的自创曲线。

由于灰阶门槛失败，未继续把饱和色、异常 FP16、色域映射、故障注入、完整 24 组性能矩阵
包装为已验收功能；生产新后端回退与默认启用也未实施。这是评估门槛停止项，不是遗漏后默认启用。

## 重现

```powershell
cmake --build --preset release --target wrc_hdr_tonemap_evaluation wrc_hdr_capture_benchmark
& ./build/cmake-release/Release/wrc_hdr_tonemap_evaluation.exe
& ./build/cmake-release/Release/wrc_hdr_tonemap_evaluation.exe --warp
& ./build/cmake-release/Release/wrc_hdr_tonemap_evaluation.exe --resources
```

评估程序返回 0 表示所有灰阶组通过，2 表示候选被桌面门槛拒绝，1 表示执行错误，77 表示无设备。
灰阶评估不是默认 CTest 的“必须通过”项；不能用 WILL_FAIL 把任意初始化错误当成成功拒绝。
`wrc_hdr_tonemap_resource_tests` 单独注册 CTest，120 次交替 1080p/1440p、读回同步、销毁资源，
预热 20 次后 private bytes 相对基线最多允许 +32 MiB。该检查不等于长期无泄漏证明。
本机120次循环通过；机器相关资源数值保留在本机忽略的性能报告，不作为双机长稳结论。

离屏基准支持 `cpu|gpu|desktop|d2d width height fps repetition`；`d2d` 仅在该测试工具中有效，
不是产品参数。预热 10 秒、采样 60 秒（旧工具此前为 5/30 秒）；JSON 明确记录实际时长。
CPU 提交与延迟读取的 GPU timestamp 分开报告，GPU 时间包含输入复制，另列 BGRA staging 复制。
没有保存真实桌面像素或发送输入。

D2D候选只进行单轮性能开销探测，没有完成完整矩阵；颜色门槛失败后不再考虑默认启用。
详细机器数据和原始日志保留在本机忽略的性能报告及构建目录，不上传个人性能报告。

## 新映射完整隔离性能矩阵

同一固定合成FP16输入；1080p/1440p、30/60目标FPS、旧GPU裁剪与新肩部，
每档各3次，共24组。每组10秒预热、60秒采样，旧/新交替串行执行，期间不编译或进行真实采集。
24组无重复键、无执行失败、无无效timestamp query。GPU计时含输入纹理复制，不包含编码或网络。

按三次运行各自p95的均值汇总，不冒充合并全部帧的分位数；同时检查每次配对增加量。
1440p各次配对均满足新增GPU p95<=1ms预算，但不能将频率/调度波动造成的均值下降宣称为加速。
总处理包含BGRA读回和CPU行复制，并非原生GPU编码路径总延迟。
没有证明CPU或FPS全面改善；60FPS是节拍目标，不意味着每次采样均稳定达到60帧。
机器相关时间、帧数、句柄和内存表格只保留在本机忽略的性能报告，提交正文记录可靠摘要。
不把单进程60秒资源快照当成长稳无泄漏证明。
