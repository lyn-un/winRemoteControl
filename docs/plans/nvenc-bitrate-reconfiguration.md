# NVENC 动态码率重配置选项：实现与验证规划

日期：2026-10-20
状态：实现及所列自动化验证完成；主观画质和其他NVIDIA显卡/驱动未验收。

实施核对修正：固定SDK头文件`nvEncodeAPI.h`注明`resetEncoder`只应与IDR一起使用，
且`enablePTD=1`时重置会强制IDR；FFmpeg确实设置`enablePTD=1`。
因此两个字段虽可独立设置，`1/0`不代表最终不发IDR。保留它作行为对照，
消除调码率附加IDR的主要候选为`0/0`。以下原规划中的独立隔离假设据此修正。

## 1. 目标与边界

保留 FFmpeg `h264_nvenc`，为码率重配置时的 `resetEncoder` 和
`forceIDR` 增加两个独立私有选项。一次编译生成补丁版 FFmpeg，再用同一套
DLL 对照不同参数组合，不为每一种组合重新编译第三方库。

目标是验证能否在保持动态码率响应的同时，减少码率更新带来的额外 IDR、
瞬时码率峰值和画质波动。不能预先认定关闭某个标志一定更好。

本轮不修改：

- QSV、AMF、x264、MF 的实现和自动选择顺序。
- 网络协议、H.264 level 协商、采集、显示缩放和 HDR 处理。
- 编码预设、GOP、VBV 预算、帧率或分辨率策略。
- 正常的首帧、周期关键帧以及接收端恢复请求。
- UI、持久化设置；不直接调用 NVIDIA 私有编码器句柄。

## 2. 当前代码与问题

固定 FFmpeg 源码基线为 `239f2c733d`。当前 `libavcodec/nvenc.c`
的 `reconfig_encoder()` 检测平均码率、最大码率或 VBV 大小变化后，
在 `reconfig_bitrate` 分支中设置：

```c
params.resetEncoder = 1;
params.forceIDR = 1;
```

随后调用 `nvEncReconfigureEncoder()`。

这两个标志不是同一件事：

- `resetEncoder`：重置内部码率控制状态，不等于销毁并重新创建编码实例。
- `forceIDR`：要求产生 IDR 关键帧。

现有应用设置的 `forced-idr=1` 是另一个选项，用于上层显式请求关键帧时的
帧类型选择；它不能控制这里的 `params.forceIDR`，本轮保持不变。

当前硬件测试观察到频繁调码率时 IDR 增多，但不能把全部画质差异只归因于
IDR：码率控制状态重置也是变量，必须分组验证。

源码定位：

- 干净基线：`build/ffmpeg-vendor/abb8e70a1c7802e6/sources/ffmpeg/libavcodec/`。
- 当前补丁构建源：`build/ffmpeg-vendor/abb8e70a1c7802e6/ffmpeg-source-patched/libavcodec/`。
- 应用设置：`src/codec/h264encoder.cpp` 的 `openCodec()`、`setBitrateKbps()`。

上述 fingerprint 是现有构建定位信息；新补丁必须生成新 fingerprint，
不得只修改构建目录中的源码冒充可重复实现。

## 3. FFmpeg 最小补丁

### 3.1 私有字段与 AVOption

在 `NvencContext` 中新增两个字段，并只在 `nvenc_h264.c` 注册：

| AVOption 名称（拟定） | 私有字段 | 范围 | 默认值 |
| --- | --- | --- | --- |
| `bitrate-reconfig-reset` | `bitrate_reconfig_reset` | 0、1 | 1 |
| `bitrate-reconfig-idr` | `bitrate_reconfig_idr` | 0、1 | 1 |

两个选项相互独立，使用 `AV_OPT_TYPE_BOOL`。默认 `1/1` 保持原有行为。
不新增 FFmpeg 公共结构体字段或公共函数，不依赖应用访问 `NvencContext` 布局。

### 3.2 重配置分支

仅在 H.264 的码率参数组重配置分支使用这两个值。共享的 `nvenc.c`
必须显式判断编码类型，避免 HEVC/AV1 因未注册选项、字段默认为零而改变行为。

单独 DAR 更新保持原逻辑。码率与 DAR 同时变化时先保守保留原来的 `1/1`，
不把纯码率实验的结论扩展到其他重配置场景；此条件要有测试和明确说明。

不改动动态码率能力判断、CONSTQP 路径、目标值比较及原有参数提交机制。
不删除其他位置的关键帧请求。

### 3.3 失败语义

核对现有 `reconfig_encoder()` 的错误日志及参数缓存行为。不能把
`AVCodecContext` 字段已更新、AVOption 设置成功或调用已发生，写成硬件已生效。

硬件测试出现重配置错误即判该组失败，不自动切换另一组后宣称通过。
若核对发现失败后缓存使后续重试或状态判断不可靠，单独列明缺陷与必要修复，
不在本补丁中顺便扩大重构范围。

## 4. 应用与测试接入

给编码器增加小型、按实例持有的 NVENC 重配置配置项，默认保持旧策略。
沿用项目风格，不引入全局可变开关。

测试程序传入两个布尔值；编码器在 `avcodec_open2()` 前调用：

```cpp
av_opt_set_int(context->priv_data, "bitrate-reconfig-reset", reset, 0);
av_opt_set_int(context->priv_data, "bitrate-reconfig-idr", forceIdr, 0);
```

这里是接口示意，不是已实现代码。两个返回值都必须检查。

- 未显式选择实验策略时，可保持上游默认，不要求旧 DLL 认识新选项。
- 显式选择实验策略时，缺少任一选项必须明确失败；不能静默当作设置成功。
- 仅应用于实际选中的 `h264_nvenc`，不得给其他编码器传这些选项。
- 策略在初始化时确定；本轮不支持运行中修改策略本身。
- 码率仍使用现有 `SetRates → setBitrateKbps → AVCodecContext` 路径动态更新。

首先只给硬件测试程序增加参数，例如：

```text
--nvenc-reconfig-reset=1 --nvenc-reconfig-idr=0
```

这些参数已接入硬件测试程序。三轮同DLL对照支持0/0，应用已接入检测到选项时的
0/0默认策略，最终构建及双机帧推进/停止/重连通过；旧库1/1兼容路径已测。
双机复验使用明确选定的应用配置，
不为一次实验增加 UI 或持久化选项。

## 6. 一次编译与部署

1. 保存最小补丁和定向测试，把所有影响产物的输入加入 fingerprint。
2. 用既有工具链构建一次新的 patched FFmpeg；保留旧产物用于回退。
3. 验证三个私有选项：既有 `forced-idr` 和两个新增重配置选项互不混淆。
4. 核对头文件、导入库、DLL、manifest 来自同一构建。
5. 所有参数组使用相同 DLL、GPU、驱动、输入和编码配置。
6. 只更新普通 `build/Release`，不额外构建 production 目录。

本轮无需为 `1/1`、`1/0`、`0/0` 分别编译 FFmpeg，也无需为了参数对照再次
构建无补丁版。已有旧 DLL 可用于检查“选项不存在”的兼容错误路径。

## 7. 验证矩阵

### 7.1 无硬件测试

- 默认值为 `1/1`，合法组合完整覆盖 `1/1`、`1/0`、`0/0`、`0/1`。
- 非法参数、未知选项有明确错误。
- H.264 纯码率重配置使用指定值。
- 相同码率不重复重配置，非正码率沿用现有语义。
- CONSTQP、不支持动态码率、单独 DAR、DAR 与码率同时变化分别覆盖。
- HEVC/AV1 不因共享字段改变原有行为。
- 保留 200 次码率调整不重建编码实例的回归。

定向桩测试只证明参数传递与分支逻辑，不代替 NVIDIA 硬件验证。

### 7.2 硬件对照

主要测试三组：

| 组别 | reset | IDR | 用途 |
| --- | --- | --- | --- |
| A | 1 | 1 | 同一补丁 DLL 的上游行为基线 |
| B | 1 | 0 | 检查reset导致的隐式IDR，不能视为无IDR模式 |
| C | 0 | 0 | 在 B 基础上隔离状态重置的影响 |

`0/1` 做独立性检查；若其结果有实际价值再扩展性能采样。

每组至少重复三次，记录 GPU 型号、驱动、FFmpeg fingerprint、参数、
分辨率、FPS、输入种子和有效采样区间。测试显式启用硬件，缺少 NVENC
时跳过，不能用软件编码替代验收。

固定 1280×720、30 FPS、相同高细节合成动画，包含：

- 1→6→1 Mbps 稳定段及固定 1、6 Mbps 对照，沿用已有严格码率门槛。
- 3/4 Mbps 高频更新及固定码率对照，保持原有 GOP、VBV、预设不变。
- 非 GOP 对齐更新，例如第 47、113 帧，避免更新恰好遇到周期关键帧。
- 在独立帧位置显式请求关键帧，验证恢复请求仍可产生 IDR。
- 一次长序列连续解码，PTS 对齐原始图像；阶段切换不排空编码器。

不要仅看 `AV_PKT_FLAG_KEY`：解析 H.264 NAL，记录真实 IDR 的 PTS，
对照固定码率的周期 IDR，区分码率更新与其他关键帧来源。

统计稳定段实际码率、亮度 PSNR、IDR 数量/位置、最大包大小、100 ms 和
1 秒媒体时间窗口的输出峰值、编码 P50/P99、帧数及解码错误。
降码率后的过渡数据另行报告，不能只丢弃过渡帧后声称响应及时。
码率按媒体时间计算，不按离线测试执行速度计算。

### 7.3 通过条件与选型

- 动态高码率稳定段至少为前低段的两倍；回落后不超过高段的 60%。
- 动态稳定段与对应固定对照偏差不超过 30%。
- 高码率阶段亮度 PSNR 不低于对应低码率阶段。
- 编码实例不重建，连续解码帧数、尺寸和 PTS 正确。
- 显式关键帧请求、周期策略和错误恢复没有回归。
- 候选策略不出现重配置失败；实际输出能证明码率仍响应。
- 报告额外 IDR 和峰值是否减少，不预设一定为零，不隐瞒质量或耗时退化。

只有 C 通过上述门槛并且结果支持保留状态，才考虑采用 C。
B在当前PTD模式下仍可能强制IDR，不作为无额外IDR的默认候选。若结果无收益或退化，保留默认 A，
不为得到预期结论放宽门槛。

单张 NVIDIA 显卡通过不能代表所有驱动和型号，交付注明已验证范围。

## 8. 回归、双机与回退

- 普通 Release 全量构建、相关测试、完整 CTest、`git diff --check`。
- QSV/AMF/x264 回归不因新选项受到影响。
- 双机复验窗口切换、滚动、视频、静止文字及断开重连；被控端明确接受，
  会话保持可见，不在无同意情况下采集或注入输入。
- 分别报告隔离基准、双机画质、网络稳定性，不用合成图 PSNR 代替用户观感。
- 同 DLL 恢复 `1/1` 可回退策略；回退第三方依赖时完整切回旧
  `FFMPEG_ROOT` 并重新部署匹配 DLL，不混用头文件和运行库。
- 关闭选项不等于驱动保证不自行产生 IDR，不承诺所有画质问题因此解决。
