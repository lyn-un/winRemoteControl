## 一 当前实现与目标

优化前，`src/capture/dxgidesktopduplicator.cpp` 的 `copyTextureToBgraFrame()` 将桌面纹理复制到同格式 staging 纹理并 Map。旧 FP16 分支在 `CopyMappedFrameToBgra()` 中逐通道执行半精度解析、白电平缩放、裁剪、sRGB 曲线和 8 位量化，最后在 CPU 合成指针；该算法仍作为 CPU 回退保留。

旧 HDR 路径：GPU RGBA16F → FP16 staging → CPU 转色 → CPU BGRA8。

目标 HDR 路径：GPU RGBA16F → GPU SDR BGRA8 → BGRA8 staging → CPU BGRA8。

已有 HDR 开关会话显示明显采集性能差异，CPU 采样发现 `powf` 热点，但不能把所有采集耗时归于幂运算。新方案同时减少 CPU 计算与有效读回字节数，不预先承诺恢复到某一 FPS。

### 不修改的范围

- 不修改 FFmpeg、QSV/AMF、WebRTC、视频协议或接收端 GPU 转色。
- 不修改采集节拍、输入即时刷新、DPI 缩放和输入启动延迟。
- 不新增 HDR 端到端传输、10 位编码、GPU 到编码器零拷贝或异步读回队列。
- 不改变固定白电平 `2.5f`；不动态读取 Windows SDR 白电平，不引入新的高光压缩算法。
- 不在本轮叠加 CPU 查表优化；保留旧 CPU 路径作为兼容回退及基准。

固定白电平加裁剪仍会丢失高光，性能改进不得描述为 HDR 色彩正确性已解决。

## 三 GPU 资源与转换流程

### 资源格式

| 资源 | 格式与用途 |
| --- | --- |
| 输入纹理 | `R16G16B16A16_FLOAT`；若采集纹理不能直接建 SRV，复制到同尺寸、带 `D3D11_BIND_SHADER_RESOURCE` 的默认纹理 |
| 输入 SRV | `R16G16B16A16_FLOAT`，按线性值读取，不使用 sRGB 解码视图 |
| 离屏输出纹理 | `B8G8R8A8_TYPELESS`，`D3D11_USAGE_DEFAULT`，绑定 render target |
| 输出 RTV | `B8G8R8A8_UNORM_SRGB`，硬件执行线性到 sRGB 转换 |
| CPU staging | 同尺寸 `B8G8R8A8_UNORM`，`D3D11_USAGE_STAGING`，CPU read，无绑定标志 |
| 常量缓冲 | 白电平系数及所需填充，符合 D3D11 对齐要求 |

先用 `CheckFormatSupport` 检查实际需要的读取、render-target 与 sRGB 写入能力，并检查资源/视图创建的 HRESULT；不因支持 FP16 采集就假定所有输出组合可用。

### 每帧顺序

1. 读取源纹理描述，检查格式、尺寸和设备归属。只对实际 FP16 输入启用本路径；SDR 和其他已有格式继续原处理。
2. 必要时 GPU 内复制到可建 SRV 的输入纹理。资源和视图按尺寸复用；不要每帧尝试创建不支持的视图。
3. 设置全屏三角形绘制状态：完整视口、不缩放、不开混合/深度/裁剪，明确设置所需状态，不依赖上次调用的管线状态。
4. 像素着色器使用 `SV_Position` 对应的整数坐标和 `Texture2D.Load()` 一对一取值，保持行方向及通道顺序。
5. 输出线性 `float4(saturate(rgb / sdrWhiteScale), 1.0f)`；由 sRGB RTV 完成曲线及量化。不得再在着色器里执行 sRGB `pow`。
6. 解除相关 SRV/RTV 绑定，将输出复制到兼容的 BGRA8 staging，Map 后按 `RowPitch` 逐行复制到原有 `vecBgraBuffer`。
7. Unmap，沿用原鼠标合成、帧索引/时间戳语义及后续处理。

`CopyResource()` 只复制兼容格式的数据，不执行 FP16 到 BGRA8 的转色。sRGB 编码发生在 RTV 写入阶段；之后复制至 UNORM staging 和 CPU 读取不会再次转换，也不能根据 staging 名称误将内容当作线性值。

非有限输入的规则需显式定义并测试：NaN 和负无穷按黑处理，正无穷按白处理，有限负值裁为零。不以旧代码对 NaN 转整数的未定义/不可靠结果作为兼容基准。CPU 回退同时采用相同异常值规则，有限值算法保持不变。

### 资源复用和失效

- 着色器及固定状态按设备创建一次；纹理/视图按尺寸创建，白电平常量只在变更时更新。
- 不把捕获到的临时纹理指针作为长期有效的资源；与 DXGI 帧释放顺序协调。
- 分辨率/格式变化、采集重初始化与 shutdown 释放相应资源；设备重建时不得复用旧设备资源。
- 仅指针移动时仍沿用缓存桌面和 CPU 指针合成，确保不把指针烘焙到缓存桌面后重复绘制。

## 四 线程与 D3D11 上下文约束

当前 `KSharedD3DDevice` 共享设备和 immediate context，创建时使用 `D3D11_CREATE_DEVICE_SINGLETHREADED`；现有 mutex 只保护创建及引用取得。新增绘制前必须核实所有实例、初始化/释放和上下文调用的线程归属。

实施顺序：先查明实际调用者及跨线程可能性，再落实以下边界：

- 若设备可能被多个线程使用，移除不成立的 SINGLETHREADED 声明；仅给新 Draw 加锁不足以修复已有并发访问。
- 保留共享设备时，为所有共享 immediate-context 操作建立一致的串行保护，包括 Copy/Draw/Map/Unmap，而非只保护转换器；不跨 `AcquireNextFrame` 等待持锁，不把 UI 回调放进锁内。
- 管线绑定状态必须具有明确所有权。确认该上下文只服务采集时，由采集转换器显式设置并解除自身状态；若发现其他渲染使用者，针对实际修改的状态保存/恢复，禁止随意 `ClearState()`。
- 新模块不自行增加工作线程或私有 GPU 设备，不隐式引入跨设备纹理共享。

如果上述核查要求显著改造设备生命周期，先更新方案并说明范围，不以大范围线程重构混入性能补丁。

## 五 开关与兼容回退

新增开发参数 `--hdr-conversion=auto|cpu`，默认 `auto`。非法值启动时报错，不增加 UI 或持久化设置，不改变 `--video-renderer` 的接收端含义。

- `auto`：FP16 优先 GPU 转色；SDR 不进入转换器。
- `cpu`：强制原 CPU 转色，供同版本 A/B 和兼容诊断使用。
- GPU 专属格式不支持、着色器编译或转换资源创建失败：记录一次原因，该采集初始化周期停用 GPU 转色，使用旧 CPU 路径；不逐帧重试或刷日志。
- 回退前解除绑定、释放已占用状态并确保原始帧仍有效；无法安全处理当前帧时按已有失败/丢弃语义返回，不输出部分转换结果。
- 设备移除/重置、DXGI access-lost 和公共 staging/Map 失败沿用采集恢复路径，不把设备整体失效冒充可用的 CPU 回退。
- 新一次显式采集初始化允许重新尝试 GPU；HDR/SDR 格式变化必须正确重建资源，避免旧纹理尺寸/格式混用。

初始化或路径变化记录请求路径、实际路径、尺寸/格式、白电平和失败 HRESULT。默认不新增逐帧日志；如需性能统计，复用 session trace 的低频汇总机制。

## 七 性能基准与验收

### 可重复隔离基准

使用相同 FP16 合成纹理，对比旧 CPU 和新 GPU 两条完整转换/读回路径；覆盖 1920×1080、2560×1440，30/60 FPS。每组预热 5 秒、采样 30 秒、重复 3 次，记录 GPU、驱动、构建版本和电源模式。

- 记录每帧总耗时、CPU 时间、Map 等待、CPU 转色/行复制耗时及 p50/p95/p99，未完成帧及截止时间错过次数单独计数。
- CPU 提交 Draw/Copy 的耗时不得称作 GPU 执行时间；仅隔离基准通过延迟读取 timestamp/disjoint query 测量 GPU 转换/复制，不逐帧等待 query。
- 分别报告有效图像字节数和 staging RowPitch；有效读回量由 8 降至 4 B/像素，不把理论数值当成 PCIe 实测流量，集显也不声称节省了独显总线传输。
- 在常见 1440p 场景，要求 CPU 帧处理时间确有下降，完整路径的中位数和 p95 不出现超过 10% 的重复性退化。否则报告瓶颈，不直接将 GPU 路径作为已验收默认交付。

### 真实场景复验

AMD HDR 显示器上，同分辨率/刷新率/编码器/码率/窗口内容分别运行 auto 与 cpu；覆盖静止、窗口切换、滚动和视频。保持真实输入操作需明确授权的现有规则。使用日志确认实际路径，防止回退后误测 CPU。

核对采集、转换、编码、接收帧率及帧丢弃，记录 CPU/GPU 资源；比较明暗、指针和高光裁剪是否与原路径一致。关闭 HDR 做 SDR 回归。没有实际运行就不能声明恢复 30/60 FPS、双机验收通过或输入延迟下降。
